# Docusaurus2PDF

Convert Docusaurus documentation sites to high-quality PDF with full MDX support.

[![npm version](https://img.shields.io/npm/v/docusaurus2pdf)](https://www.npmjs.com/package/docusaurus2pdf)
[![License: MIT](https://img.shields.io/npm/l/docusaurus2pdf)](LICENSE)
[![Node.js](https://img.shields.io/node/v/docusaurus2pdf)](package.json)

## Features

- **Full MDX Support** - Parses all Docusaurus components including DocCardList, Details, Admonitions, Tabs
- **LaTeX-based PDF Generation** - Uses LaTeX for professional-quality PDF output with proper typography
- **Math Equations** - Supports inline `$...$` and block `$$...$$` LaTeX math equations
- **Mermaid Diagrams** - Converts Mermaid diagrams to PNG using mmdc CLI
- **PlantUML Integration** - Generates vector (SVG/EPS) or high-resolution PNG diagrams (up to 600 DPI)
- **Code Block Options** - Supports `title="file.js"` and `showLineNumbers` attributes
- **Emoji Rendering** - LuaLaTeX renders emojis in black & white using Twemoji Mozilla font
- **Multilingual** - Supports English, Czech, Slovak, and other UTF-8 languages
- **Section Filtering** - Generate PDFs for specific sidebar sections only
- **Docker-based LaTeX** - No local LaTeX installation required
- **Multiple Output Modes** - Per-language, per-section, or single PDF

## Quick Start

```bash
# Install
npm install
npm run build

# Generate PDF from your Docusaurus site
npx docusaurus2pdf -i ./my-docusaurus-site -o ./pdf-output
```

## CLI Options

| Option | Alias | Description | Default |
|--------|-------|-------------|---------|
| `--input <path>` | `-i` | Input Docusaurus site directory | (required) |
| `--output <path>` | `-o` | Output directory for PDFs | `./pdf-export` |
| `--engine <engine>` | `-e` | LaTeX engine (lualatex, xelatex, pdflatex, tectonic) | `lualatex` |
| `--single` | `-s` | Generate single PDF with all content | `false` |
| `--per-language` | `-l` | Generate separate PDF per language | `true` |
| `--tex-only` | - | Generate .tex files only, skip PDF compilation | `false` |
| `--compile-only` | - | Compile existing .tex files to PDF | `false` |
| `--no-docker` | - | Use local TeX installation instead of Docker | `false` |
| `--sections <names>` | - | Comma-separated section names to generate | (all) |
| `--strip-numbering` | - | Strip manual numbering from headings (e.g., "3. Title" → "Title") | `false` |
| `--convert-emoji` | - | Convert emoji to text (e.g., "📷" → "[Camera]") for PDF output | `false` |
| `--suppress-caption-numbers` | - | Suppress automatic figure numbering in captions | `false` |

## Usage Examples

### Basic Usage

```bash
# Generate PDFs per language (default behavior)
npx docusaurus2pdf -i ./docs -o ./pdf-output

# Generate single PDF with all content
npx docusaurus2pdf -i ./docs -o ./pdf-output --single

# Use specific LaTeX engine
npx docusaurus2pdf -i ./docs -o ./pdf-output --engine xelatex
```

### Diagram Support

The tool automatically converts **PlantUML** and **Mermaid** diagrams to SVG format for high-quality PDF output:

- **Mermaid**: Server-side rendered using jsdom (no browser needed)
- **PlantUML**: Local generation via Java JAR (if available) or TeaVM PlantUML.js (pure JavaScript fallback)

**Note**: All diagrams are converted to SVG format. For LaTeX compilation, use `lualatex` or `xelatex` (recommended) as they have built-in SVG support via the `svg` package. The `pdflatex` engine is not supported for documents containing diagrams.

Both diagram types use LaTeX's `\includesvg` command and maintain vector quality in the output PDF. No additional configuration needed - diagrams are automatically detected and converted.

### Section Filtering

Generate PDFs only for specific sidebar sections:

```bash
# Single section
npx docusaurus2pdf -i ./docs -o ./pdf-output --sections "tutorials"

# Multiple sections
npx docusaurus2pdf -i ./docs -o ./pdf-output --sections "tutorials,guides,api"
```

Available section names are derived from your Docusaurus sidebar configuration (autogenerated directories or explicit categories).

### TeX Output

```bash
# Generate only .tex files (for custom processing)
npx docusaurus2pdf -i ./docs -o ./pdf-output --tex-only

# Compile existing .tex files to PDF
npx docusaurus2pdf -i ./docs -o ./pdf-output --compile-only
```

## Docusaurus Plugin

For automatic PDF generation during your Docusaurus build, use the plugin:

```javascript
// docusaurus.config.js
module.exports = {
  // ... your config
  plugins: [
    [
      'docusaurus2pdf/plugin',
      {
        outputDir: './pdf-output',
        single: false,
        sections: ['tutorials', 'guides'],
      },
    ],
  ],
};
```

### Plugin Options

| Option | Type | Description | Default |
|--------|------|-------------|---------|
| `outputDir` | `string` | Output directory for PDFs | `./pdf-export` |
| `single` | `boolean` | Generate single PDF | `false` |
| `sections` | `string[]` | Sections to include | all |
| `texOnly` | `boolean` | Generate only .tex files | `false` |
| `stripNumbering` | `boolean` | Strip manual numbering from headings | `false` |
| `suppressCaptionNumbers` | `boolean` | Suppress figure numbering in captions | `false` |
| `onSuccess` | `function` | Callback after generation | - |

## MDX Component Support

| Component | LaTeX Output |
|-----------|--------------|
| `DocCardList` | `\begin{itemize} ... \end{itemize}` |
| `DocCard` | Bold text with optional description |
| `Details` | `tcolorbox` with title |
| Admonitions (`:::tip`, etc.) | Colored `tcolorbox` |
| Tabs (`<Tabs><TabItem>`) | Sequential content with bold labels |
| Math Equations (`$...$`, `$$...$$`) | Inline math or display math blocks |
| Mermaid Diagrams | `\includesvg{img/mermaid_hash.svg}` |
| Code Blocks (`title`, `showLineNumbers`) | `\begin{lstlisting}[caption=...,numbers=left]` |
| Emojis (LuaLaTeX) | `\emoji{name}` with Twemoji font |

## Requirements

- Node.js 18+
- LaTeX with `lualatex` or `xelatex` (for PDF compilation with SVG support)
- Optional: Java + PlantUML (for better PlantUML diagram quality)

### LaTeX Setup

For PDF compilation with SVG diagram support, install a modern LaTeX distribution:

**macOS:**
```bash
brew install --cask mactex
```

**Ubuntu/Debian:**
```bash
sudo apt-get install texlive-full
```

### Diagram Generation

**Mermaid diagrams** work out of the box (server-side rendering via jsdom).

**PlantUML diagrams** have two options:
1. **Recommended**: Install Java and PlantUML for best quality:
   ```bash
   # macOS
   brew install plantuml

   # Ubuntu/Debian
   sudo apt-get install plantuml
   ```
2. **Fallback**: Uses bundled TeaVM PlantUML.js (pure JavaScript, no Java needed, ~8MB)

## Programmatic API

```typescript
import { Renderer, SiteLoader } from 'docusaurus2pdf';

const siteLoader = new SiteLoader();
const site = await siteLoader.load('./my-docusaurus-site');

const renderer = new Renderer({
  OutputDir: './pdf-output',
  Engine: 'lualatex',
  Sections: ['tutorials', 'guides'],
});

// Generate single PDF
await renderer.renderSingle(site);

// Or per language
await renderer.renderPerLanguage(site);

// Or per section
await renderer.renderPerSection(site);
```

## Troubleshooting

### No LaTeX installation found

If you see this error, either:
1. Install Docker and ensure it's running
2. Install a local LaTeX distribution and use `--no-docker`

### PlantUML diagrams not appearing

Ensure:
- PlantUML code blocks use triple backticks with `plantuml` language
- PlantUML server is accessible (uses public PlantUML server by default)

### PDF compilation fails

- Check the `.log` file in the output directory for LaTeX errors
- Try `--tex-only` to inspect the generated .tex file
- Ensure enough memory is available for LaTeX compilation

## Origin

This project was inspired by a school assignment at VŠPJ Jihlava (2007–2008),
originally assigned by Tomáš Richta — a DokuWiki-to-LaTeX converter written in
C. Years later, I used that original codebase as a starting point, feeding it
into LLM-based tools. What began as a simple port evolved through Go and
eventually into TypeScript, driven by the complexity of real-world Docusaurus
projects. While this implementation shares no code with the original, the core
idea carried through from the very beginning.
